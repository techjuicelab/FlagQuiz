# FlagQuiz UI 개편 계획

작성일: 2026-09-26 · 상태: 사용자 승인 후 구현 · 검증 결과는 VERIFICATION.md 참조

## 1. 확정된 방향

- 밝고 단정한 iOS 앱 느낌으로 재설계한다.
- 국기·삽화·음성이 중심이 되도록 배경 장식과 동시에 강조되는 정보를 줄인다.
- 스티커·경험치·레벨·보물상자 보상은 유지한다. 평소에는 작게, 획득 순간과 결과에서는 분명하게 보여 준다.
- 일반 설정은 한 번 탭해서 연다. `아빠 설정`이라는 이름과 길게 누르기 조건을 없앤다.
- 기존 디자인 문서는 당시 결정의 이력이다. 이번 사용자 선택을 새 시안의 기준으로 삼는다.
- 이 문서와 함께 제시하는 시안의 이름·진행률·점수는 예시이며 실제 사용자 기록이 아니다.

## 3. 정보 구조와 화면 흐름

기본 내비게이션은 `놀이 / 도감 / 기록` 세 곳이다. 설정은 상단 톱니 아이콘과 라벨로 별도 진입한다.

### 놀이

- 홈: 국기 놀이·그림 놀이·지도 놀이·수도 놀이 4개를 현재와 같은 순서로 둔다.
- 국기: 보고 고르기 / 듣고 국기 찾기 / 말로 답하기 / 이름 쓰기.
- 그림: 그림 보고 고르기 / 명소 보고 고르기.
- 지도: 나라의 위치 찾기. 방식이 하나이면 추가 선택 없이 시작한다.
- 수도: 공부하기 / 퀴즈를 명확히 구분한다. 퀴즈에서는 듣고 국기 고르기 / 말로 답하기를 고른다.
- 주제 안에서 최근 사용 방식을 알아보기 쉽게 표시하되, 버튼 위치를 자동으로 바꾸지 않는다.
- 현재 난이도·대륙·문제 수는 짧은 범위 요약으로 표시하고 설정으로 연결한다.
- 오늘의 도전은 홈의 보조 항목으로 유지한다. 주제 선택보다 강하게 강조하지 않는다.

### 도감과 기록

- 도감은 기존 스티커 판의 기능을 계승한다. 나라 보기와 수집 현황을 같은 곳에서 확인한다.
- 기록은 요약 지표를 먼저, 놀이별 기록·최근 놀이·배지를 아래에 둔다.
- 학습 수치와 보상 수치를 화면마다 서로 다른 값처럼 중복 표현하지 않는다.
- 기존 기록 내보내기와 삭제는 설정의 기록 관리로 연결한다. 신규 복원 기능은 이번 UI 범위에 포함하지 않는다.

### 설정

- 한 번 탭으로 열고, 상단 제목과 `돌아가기`를 제공한다. 전체 설정 잠금은 두지 않는다.
- `놀이 조건`: 이름, 지원되는 놀이의 2인 대결, 난이도, 대륙, 문제 수, 제한 시간, 복습 빈도.
- `소리`: 효과음, 이름 읽어주기, 홈·도감 배경음, 정답 소리.
- `오프라인 저장`: 저장 상태, 전체 저장, 진행률, 실패·이어받기, 사용 방법.
- `기록 관리`: 기록 내보내기, 기록 모두 지우기. 삭제 직전 기존 확인 절차를 유지한다.
- `앱 정보`: 자산 출처와 기기 내 기록 저장 안내.
- 변경은 기존 저장소에 즉시 반영하되 화면 전체를 다시 그리지 않는다. 선택·입력·스크롤·포커스를 유지한다.
- 현재 놀이에 적용되지 않는 옵션에는 이유를 표시한다. 저장된 다른 놀이의 선택값은 지우지 않는다.
- 처음 개편에서는 설정 진입을 놀이 시작 전과 판 종료 후에 제공한다. 진행 중인 문제의 조건 변경은 추가하지 않는다.

## 4. 기기별 배치

| 화면 | 아이폰 및 좁은 iPad 창 | 충분히 넓은 iPad 창 |
| --- | --- | --- |
| 기본 화면 | 상단 제목·설정, 하단 3개 내비게이션 | 왼쪽 내비게이션, 오른쪽 콘텐츠 |
| 홈 | 큰 놀이 카드 2×2와 작은 진행 요약 | 여유 있는 놀이 카드 2×2, 보조 요약 영역 |
| 문제 | 문제 영역 한 열, 선택형 보기 2×2 | 왼쪽 문제, 오른쪽 답과 보조 행동 |
| 수도 공부 | 내용 카드 한 열, 아래 이전·다음 | 넓은 내용 카드와 일정한 이전·다음 위치 |
| 설정 | 읽기 쉬운 한 열 목록 | 폭을 제한한 목록 또는 범주와 상세 두 영역 |
| 도감 | 작은 화면에 맞는 유동 그리드 | 사용 가능한 폭에 맞춰 열 수 확대 |

- 기기 이름이나 화면 방향만으로 분기하지 않고 실제 사용 가능한 폭으로 전환한다.
- iPad 분할 화면에서 폭이 부족하면 아이폰 구조로 자연스럽게 돌아간다.
- 퀴즈·공부 중에는 기본 내비게이션을 숨기고, 그만하기 또는 돌아가기와 진행 표시를 제공한다.
- 아이폰의 노치·홈 표시줄 안전 영역을 확보한다. 하단 내비게이션이 본문이나 답 버튼을 가리지 않는다.
- 기본 글자 크기에서는 핵심 문제와 답을 한 화면에서 사용할 수 있게 한다.
- 글자 확대, 작은 화면, 긴 나라 이름에서는 스크롤을 허용한다. 글자를 줄이거나 내용을 잘라 맞추지 않는다.
- 설정·도감·기록은 필요한 만큼 스크롤하며, 이전의 “모든 화면 스크롤 금지” 원칙은 적용하지 않는다.

## 5. 시각 기준과 공통 부품

색은 아래 후보를 시안에서 검토한 뒤 확정한다. 배경은 단색을 기본으로 한다.

| 역할 | 밝은 화면 후보 |
| --- | --- |
| 바탕 | `#F5F6F8` |
| 표면 | `#FFFFFF` |
| 기본 글자 | `#182334` |
| 보조 글자 | `#5F6C7D` |
| 주요 행동 | `#2563EB` |
| 구분선 | `#E8EEF6` |

- 글꼴은 `-apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", "Noto Sans KR", sans-serif` 등 시스템 스택을 사용한다. 외부 웹폰트를 불러오지 않는다.
- 제목·본문·보조 설명의 크기와 굵기를 구분한다. 모든 문장을 굵게 표시하지 않는다.
- 주요 큰 버튼은 높이 56~64px, 나머지 조작 영역은 최소 44×44px을 기준으로 한다.
- 국기·그림은 충분히 크게 유지한다. 이모지는 놀이 주제·보상에서 제한적으로 쓰고 UI 아이콘은 같은 선 스타일로 통일한다.
- 카드에는 얇은 선 또는 약한 그림자를 쓴다. 모든 버튼에 그림자·색 배경·굵은 테두리를 동시에 넣지 않는다.
- 선택·정답·오답은 색뿐 아니라 체크, 테두리, 짧은 문구로도 구별한다.
- 공통 부품: 앱 내비게이션, 페이지 머리, 주제 카드, 방식 선택, 설정 행·스위치, 진행 표시, 듣기 버튼, 답 카드, 피드백, 오프라인 상태, 확인 대화상자.
- 다크 모드는 의미별 토큰을 별도로 정의한다. 밝은 화면 색을 그대로 뒤집지 않는다.
- 동작 줄이기 설정을 존중하고, 화면을 읽는 보조 기술의 이름·선택 상태·진행 알림·포커스 순서를 유지한다.
- 본문 200% 확대, 키보드 입력, 긴 이름, 고대비 상황에서도 조작과 정보에 접근할 수 있게 검증한다.

## 6. 기능·기록·캐시 보존 조건

- 출제·채점·학습 기록 엔진을 디자인 개편과 함께 재작성하지 않는다.
- `flagquiz.v1` 키와 `settings`, `stats`, `countries`, `axes`, `badges`, `history`, `daily`, `chest`를 보존한다. 근거: `js/storage.js:8`.
- 스티커·레벨·경험치·누적 점수의 기존 계산을 사용한다. 표시용 새 카운터를 만들지 않는다.
- 수도 공부는 무채점·이전/다음 이동을 유지한다. 퀴즈로 자동 진입시키지 않는다. 근거: `js/app.js:874`.
- 수도 퀴즈의 한 판 중복 없음, 틀린 문제 강제 재출제 없음, 국기 놀이의 기존 대결 규칙을 보존한다.
- 화면 이동 때 재생 음성·마이크·자동 다음 문제 예약을 정리하는 처리를 새 내비게이션에도 연결한다. 근거: `js/app.js:150`.
- 기존 국기·그림·녹음·음악 파일 경로와 manifest를 유지한다. 외부 이미지·음성 서비스 호출을 UI에 추가하지 않는다.
- `flagquiz-flags-v1`, `flagquiz-art-v1`, 특히 기존 오디오 캐시 `flagquiz-v4`를 보존한다. 근거: `sw.js:6`.
- 변경된 앱 화면은 기존 셸 콘텐츠 해시 방식으로 갱신한다. 새 로컬 화면 자산은 셸 캐시 목록에 포함한다. 근거: `scripts/build-site.mjs:91`.
- 전체 다운로드·진행률·재시도·이어받기를 유지하고, 저장 중 설정을 닫아도 작업 상태를 잃지 않게 한다.
- 연결이 끊겼을 때 말하기에서 터치 답변으로 이어지는 처리와 기기 내 기록 저장을 유지한다.
- 옛 시안의 `/_blob/` 주소 대신 저장소의 실제 `flags/`·`images/` 자산을 사용한다.

| 단계 | 범위 | 완료 기준 |

| 1. 시안 검토 | 아이폰·iPad 홈, 문제, 설정과 공통 토큰 | 한 번 탭 설정, 주제 4개, 작아진 보상, 기기별 배치가 시안에서 확인된다. |

| 6. 오프라인·접근성 | 다운로드 관리, 예외 상태, 확대·다크 | 기존 캐시를 보존한 갱신 및 전체 저장 후 오프라인 재실행이 통과한다. |
| 7. 배포 확인 | 테스트, 실제 배포, 설치 앱 갱신 | 새 화면이 공개 앱에 반영되고 기존 사용자 기록·다운로드가 유지된다. |

## 8. 최종 검증 항목

- 자동 검증: `npm test`, `npm run build`, `npm run verify` 및 변경한 내비게이션·설정의 회귀 검사.
- 화면 검증: 아이폰 작은 폭·일반 폭, iPad 세로·가로, 좁은 분할 화면에서 잘림·가로 넘침·가려진 버튼 없음.
- 조작 검증: 터치, 키보드, 설정 돌아가기, 빠른 연속 탭, 화면 이동 중 늦게 끝나는 음성·타이머.
- 학습 검증: 국기·그림·명소·지도·수도, 수도 공부 완료와 재공부, 정답·오답·힌트, 2인 대결, 결과·보상.
- 기록 검증: 개편 전 표본 기록을 불러온 뒤 화면을 둘러보기만 해서는 통계가 바뀌지 않음. 설정 변경 시 학습 기록 유지.
- 오프라인 검증: 저장 완료 → 네트워크 끊기 → 앱 재실행 → 처음 보는 그림·국기·음성 사용 → 기록 확인.
- 다운로드 검증: 중단·재연결·이어받기, 설정 닫기·다시 열기, 기존 미디어 캐시가 있는 상태의 앱 갱신.
- 표현 검증: 밝은 화면·다크 모드·동작 줄이기·본문 확대에서 가독성·초점·선택 상태 확인.
- 실제 iPhone/iPad Safari 및 홈 화면 설치 앱 검증을 브라우저 크기 모의 검증과 구분해 기록한다.
- 기능을 숨겨서 화면을 정리하지 않는다. 이동한 기능은 새 위치와 진입 방법을 사용자 안내에 반영한다.

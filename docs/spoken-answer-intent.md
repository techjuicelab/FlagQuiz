# 말한 문장에서 최종 답 찾기

세 말하기 모드(`voice`, `capitalVoice`, `country-chain`)는 녹음 → NAS STT → 최종 답 선택 → 기존 채점 순서를 사용한다. STT는 글자를 만드는 역할이고, 이 단계는 아이가 그 문장에서 무엇을 답으로 골랐는지를 찾는다.

- `뭐지… 음… 스페인 아니고 포르투갈` → 포르투갈을 채점한다.
- `포르투갈 아니고 스페인` → 스페인을 채점한다. 문제 정답이 포르투갈이어도 포르투갈로 바꾸지 않는다.
- `포르투갈인지 스페인인지`·부정만 있는 말·확인 질문·다른 사람의 말 인용만 있는 경우 → 점수와 차례를 유지하고 하나의 답을 다시 말하도록 안내한다.
- `아빠는 대한민국이라는데 나는 일본으로 할래` → 뒤에서 명확히 고른 자기 답 일본을 채점한다. 앞의 인용·질문 뒤에 `나는`·`내 답은`·`이번에는` 같은 직접 선택 표현이 있어도 뒤 문장이 부정이나 선택 미정이면 다시 답한다. 따옴표가 남은 문장은 보수적으로 다시 답한다.
- `다시. 스웨덴. 스웨덴. 그는.` → 같은 이름을 여러 번 말한 답은 스웨덴 하나로 채점한다. 이처럼 다른 후보 없이 문장으로 분리된 미완성 시작말(`그는`·`나는`·`저는`·`이건`·`그건`)만 끝에 남으면 제거한다. 완전한 문장·질문·부정·인용·다른 후보는 이 보완으로 추정하지 않는다.
- 국기·수도 말하기의 명시적 포기는 기존 “몰라요” 흐름을 사용한다. 나라 이어 말하기는 포기 표현에도 현재 차례를 유지하고 다시 답하도록 안내한다. 앞에서 도움을 요청했다가 뒤에서 답을 고르면 답이 우선한다.

`js/spoken-answer.js`는 모든 나라 또는 수도의 이름·별칭을 검사한다. 인도/인도네시아, 기니/기니비사우처럼 긴 이름 안의 짧은 이름을 별도 답으로 세지 않는다. 문장에 나온 이름과 정정 표현으로 최종 직접 선택을 찾으며 현재 문제·정답·보기는 입력으로 받지 않는다. 일반 문장 속 임의의 낱말에 느슨한 이름 판정을 적용하지 않는다. 짧은 단독 답의 기존 발음 허용도 전체 목록에서 유일한 후보일 때만 사용한다.

마이크 권한과 준비가 완료되면 45ms의 작은 비프음을 낸다. 비프음이 끝나기 전에는 마이크를 음소거하고 녹음기를 시작하지 않는다. 소리 끄기와 재생 실패에서는 녹음을 그대로 시작하며, 이어 듣기의 내부 무음 구간 교체에서는 비프를 반복하지 않는다.

세 말하기 모드 모두 발화 뒤 200ms 침묵을 기다린 뒤 전사를 요청하며 20ms 간격으로 확인한다. 이는 전사·네트워크 시간을 제외한 발화 종료 대기 시간이다. 150ms의 말 중간 쉼은 보존하며 200ms보다 긴 쉼은 완결된 녹음으로 해석한다. 발화 길이는 12초까지 보존한다. 사용자가 요구한 전체 지연 목표는 마지막 발화 종료부터 답 표시까지 0.5–1초이며, 음성·선택 공급자와 NAS·네트워크 시간을 포함한 실측으로 판단한다. 정답은 이름을, 오답·포기는 정답과 전체 설명을 읽고 다음 문제로 자동 진행한다. 미인식과 미선택에는 같은 문제에서 수동으로 마이크를 다시 누르거나 글자로 답한다.

## Jev 선택 보조

[TypeSafe의 후보 추출·선택 방식](https://docs.typesafe.ai/cookbooks/pre_parsed_value_extraction_cookbook)에 따라 코드가 먼저 실제 발화의 후보를 찾는다. 서버에 선택 키가 설정돼 있으면 명확한 답과 명시적 최종 선택이 있는 복잡한 문장 모두 Jev `Choice`로 최종 선택을 확인한다. 실제 발화 후보와 `unresolved`/`giveup`만 보내며 출제 정답·사진·보기·아이 이름·계정은 보내지 않는다. 모델이 말하지 않은 나라를 추론하거나 채점을 직접 결정하지 못하도록 반환 코드를 실제 후보와 다시 대조하고 최종 나라 코드와 문제 정답의 비교는 기존 채점 엔진이 맡는다. 명시적 정정으로 이미 확정한 답은 모델이 앞의 다른 후보로 바꾸지 못한다.

`server/answer-resolution.mjs`는 `jev-1.13.0`을 고정 사용한다. 최대 3초, 전사 한 번당 최대 한 번 호출하고 자동 재시도하지 않는다. 부정·인용·선택 미정·판정기를 조작하는 명령은 모델 선택으로 덮지 않는다. 미설정 키, 장애, 시간 초과, 잘못된 형식, 후보 밖 결과 또는 보수적 기준 미달은 기존 규칙 결과를 유지한다. 명확한 이름은 계속 채점할 수 있고 규칙이 미해석한 문장은 재질문한다. 유료 선택 직전의 권한 오류는 이 fallback으로 삼키지 않으며 공급자 호출 전에 중단한다.

`TYPESAFE_API_KEY`는 서버의 선택 설정이며 기본값은 비어 있다. 키 값은 서버 실행 시 1Password에서 주입한다. 브라우저·빌드 결과·로그·학습 기록에는 저장하지 않는다. 기존 배포 설정에 이 키가 없으면 규칙 판정만 동작한다. 서버에 키를 연결하기 전에도 모든 STT 모드는 사용할 수 있다.

현재 기준은 `confidence >= 0.9`, 선택 확률 `>= 0.95`, 다음 후보와 차이 `>= 0.8`이다. 이 수치는 도메인 정확도를 보장하는 값이 아니다. 공식 문서에 따르면 [confidence는 선택 확률 분포의 집중도](https://docs.typesafe.ai/confidence)이며, [CJK 지원의 정확도 한계](https://docs.typesafe.ai/models#language-support)와 [적대적 입력·선택지 순서 한계](https://docs.typesafe.ai/model-jaggedness/jev-1.13)가 있다. 실제 한국어 어린이 전사와 정답표를 사용해 오정답 인정률·불필요한 재질문율·지연을 따로 측정해야 한다.

## 확인 범위

자동 검사에서는 규칙의 문장 반전·부정·인용·미정·수도·별칭, 모델 응답 형식·임계·후보 밖 결과·취소·장애, 앱의 점수/문제/차례 유지와 자동 다음을 확인한다. 합성 브라우저 마이크는 실제 인증·녹음 처리·HTTP 전송·최종 채점 흐름을 검사하는 도구이며 실제 iPhone 마이크나 어린이 발화 정확도 검증을 대신하지 않는다.

2026-10-04에는 1Password의 서버 전용 키로 실제 Jev API를 호출하여 첫 합성 전사 33건과 수도·나라 이어 말하기 추가 6건, 총 39건을 비교했다. [재현용 합성 문장과 정답 라벨](../tests/fixtures/spoken-answer-synthetic-2026-10-04.json)에 두 corpus를 보존하며 실제 모델 응답 전체나 확률을 테스트의 기대 결과로 고정하지 않는다.

| 항목 | 이번 합성 비교 결과 |
| --- | --- |
| 전체 문장 | 39건, 실제 Jev 요청 26회, Jev 답 보완 18건 |
| 첫 corpus의 복잡한 나라 최종 선택 문장 | 20건 중 19건이 호출 조건을 통과했고 14건을 Jev가 올바른 답으로 보완; 나머지 6건은 재답변 유지 |
| 추가 수도·나라 이어 말하기 | 복잡한 수도 2건·나라 이어 말하기 2건 모두 Jev가 라벨의 답으로 보완; 선택 미정 2건은 API 호출 없이 재답변 유지 |
| 의도한 답과 다른 이름을 인정 | 0건 |
| 라벨과 결과 일치 | 첫 corpus 25/33건, 추가 6/6건; 합계 31/39건이며 나머지 8건은 재답변 유지 |
| 모델 API 구간 지연(최초 22회) | 120–227ms, p50 148.5ms·p95 199ms; 녹음·Groq 전사 시간 제외 |
| provider 장애 | 0건 |

첫 corpus에서 보완하여 인정한 14건은 모두 정답 라벨과 일치했다. 복잡한 문장 5건은 모델이 라벨과 같은 후보를 선택해도 선택 확률이 `0.95`보다 낮아 재답변으로 남겼고, 1건은 호출 조건에서 제외했다. 별도 스트레스 문장 3건도 모두 재답변을 유지했다. 추가 모드 6건에서도 다른 이름을 인정하지 않았다. 신뢰·확률 기준은 이 비교 결과에 맞춰 낮추지 않았다. 답을 확정하지 않은 경우를 정답 성공으로 합산하여 전체 성공률 100%로 표현하지 않는다.

재비교할 때는 fixture의 각 `text`·`mode`를 `createAnswerResolver()`에 전달하고 사람이 붙인 `expectedStatus`·`expectedCode`와 대조한다. 복잡한 문장의 답 보완 수, 다른 이름 인정 수, 확정하지 않은 수와 모델 구간 지연을 따로 집계한다. 키는 1Password에서 서버 실행 시 주입하며 fixture에는 넣지 않는다. 합성 표본의 다른 이름 인정 0건은 실제 어린이 발화의 오류율을 보장하지 않는다. NAS의 키 주입·배포·운영 호출 성공은 별도 확인 대상이며 이 비교로 완료로 표시하지 않는다. 실제 iPhone/iPad 어린이 발화와 한국어 전사의 정확도·전체 응답 지연은 아직 검증하지 않았다.

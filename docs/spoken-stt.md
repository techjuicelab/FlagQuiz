# 모든 말하기 놀이의 STT 설계

2026-10-06 구현, 2026-10-15 공급자·비용 계약 갱신. 국기 보고 나라 말하기(`voice`), 국기 보고 수도 말하기(`capitalVoice`), 나라 이어 말하기(`country-chain`)는 같은 NAS 인증 경로를 쓴다. 서버와 기기가 지원하면 Soniox 실시간 인식을, 스트리밍 미지원 기기는 WAV 녹음 뒤 같은 Soniox 실시간 모델로 전사한다. 키가 없으면 글자로 답한다. 실시간 경로는 [발화 중 이름 확정](streaming-speech-design.md)에 정리했다. 브라우저 `SpeechRecognition`과 iOS 키보드 받아쓰기 설정에 의존하지 않으며 기기 내 음성 인식 모델을 추가하지 않는다.

읽어주기(TTS)는 미리 생성한 Typecast Sua MP3 1,319개를 재생하고 기기의 오프라인 저장 기능을 그대로 사용한다. 이용 중 Soniox로 음원을 새로 생성하지 않는다. STT의 문맥 사전은 음성 인식 요청에 함께 보내는 텍스트이고, 들려주는 MP3와 역할이 다르다. 현재 실시간·녹음 후 전사 모두 이 사전과 고정 프롬프트를 보내지 않는다. 전사 이후 이름·별칭을 해석하는 로컬 목록은 그대로 유지한다.

## 아이가 답하는 흐름

| 상태 | 화면과 동작 | 말하기 퀴즈 제한시간 |
| --- | --- | --- |
| 마이크 준비 | 로그인·기기 지원과 실제 마이크 연결을 확인한다. 입력을 음소거한 상태에서 뚜렷한 준비 비프를 재생한다 | 멈춤 |
| 녹음 | “듣고 있어요”를 표시한다. 현재 사람의 답 하나를 받는다 | 실제 녹음 시간 측정 |
| 녹음 정리 | 스트리밍은 확정 이름 또는 의미적 말끝에서 즉시 입력을 멈춘다. 파일 경로는 무음 후 녹음을 마친다 | 멈춤 |
| 답 확인 | NAS가 STT 결과를 기다리는 동안 새 녹음을 시작하지 않는다 | 멈춤 |
| 최종 답 선택과 채점 | 현재 문제·세션을 확인하고 문장에서 고른 이름 하나를 기존 채점에 전달한다 | 결과에 따라 진행 |

마이크는 문제 시작과 답 설명 뒤 다음 문제에서 자동으로 연다. 실제 마이크·오디오 처리·서버 연결이 준비되면 880Hz·120ms·gain 0.2의 비프를 한 번 내고, 재생이 끝난 뒤에만 녹음 표본을 받는다. 권한 허용을 기다리는 동안에는 울리지 않으며, 효과음 OFF에서도 준비음은 재생한다. 비프 실패·거절·시간 초과는 녹음을 시작하지 않고 재시도를 안내한다. 놀이가 이어질 때는 음소거한 마이크·AudioContext·Worklet을 재사용하고, 홈·숨김·멈춤·오류에서는 해제한다. 한 녹음 구간은 최대 12초이며, 세 모드 모두 아이가 생각하는 무음 대기에는 마이크를 유지하고 기기 안에서 녹음 구간만 교체한다. 무음만 받으면 유료 전사를 보내지 않는다. 권한·녹음·연결·사용량 오류에는 같은 문제·플레이어 차례·점수·힌트를 유지하고 글자 입력을 펼친다. 아이나 어른이 마이크를 다시 눌러 시도할 수 있으며 실패한 유료 요청은 자동으로 반복하지 않는다. “음…”이나 이름을 판정하지 못한 발화 뒤에는 마이크를 다시 누르지 않아도 같은 문제에서 계속 듣는다. 유효한 나라·수도를 인식하면 기존 규칙대로 채점한다.

제한시간을 켠 판에서는 권한·녹음 정리·전사 대기 시간을 제외한다. 녹음할 때와 같은 문제에서 글자로 답하거나 수동 재시도를 기다릴 때는 기존 남은 시간이 흐른다. 서버 지연 때문에 답을 말한 아이의 시간이 줄어들지 않도록 하면서 수동 입력의 기존 시간 규칙을 유지한다.

최종 인식 문자는 먼저 세 모드가 공유하는 `FQ.spokenAnswer.resolve()`로 해석한다. 모든 나라 또는 수도의 실제 이름·별칭과 정정 표현을 검사하여 `answer`·`retry`·`giveup`을 정한다. 현재 문제의 정답·보기는 이 함수의 입력에 포함하지 않는다. `answer`일 때만 선택한 정식 이름을 `interpret()`·`checkText()` 또는 나라 이어 말하기 matcher로 전달한다. 원문에서 현재 정답과 닮은 이름만 골라 채점하지 않는다.

예를 들어 “뭐지… 스페인 아니고 포르투갈”은 포르투갈, “포르투갈 아니고 스페인”은 스페인이 답이다. “포르투갈인지 스페인인지”·부정만 있는 말·확인 질문·인용만 있는 말은 같은 문제에서 다시 답한다. 단독 도움 요청은 재답변으로 남기고, 국기·수도 퀴즈의 명시적 “몰라요”·패스는 기존 포기 흐름을 사용한다. 나라 이어 말하기는 포기 표현에도 현재 차례에서 다시 답하도록 안내한다. 인도네시아의 인도, 기니비사우의 기니처럼 긴 이름의 일부를 별도 답으로 세지 않는다. 망설이는 말 뒤의 비슷한 발음과 긴 이름의 중간 음절이 빠진 발음도 전체 목록에서 하나의 후보로 구별되면 보완한다. “뭐.. 이게 맞나. 포르.. 갈”은 포르투갈, “포도칼”처럼 STT가 다른 철자로 적은 비슷한 발음도 유일하게 구별되면 포르투갈로 판정한다. 짧고 모호한 조각이나 부정한 이름은 답으로 추정하지 않는다. [최종 답 규칙과 Jev 선택 보조](spoken-answer-intent.md)에 문장 예와 해석 한계를 정리했다.

WAV 녹음 후 전사를 선택한 경우에는 세 모드 모두 20ms마다 말소리를 확인하고, 말소리 뒤 800ms의 침묵을 감지하면 녹음을 마친다. 200ms 종료 기준에서 긴 이름 중간의 220–500ms 쉼이 답을 잘라내던 회귀를 보완한 기준이다. 세 모드 모두 짧은 자음 사이 80ms 공백을 두고 실제 유성음 시간을 누적해 100ms를 확인하고, 발화가 확인되면 약한 끝음절도 보존한다. 기본 연속 대기에서는 마이크 시작 직후의 작은 목소리도 말끝의 에너지 하강으로 발화 후보를 복구하고, 후보가 진행 중이면 무음 구간 교체로 첫 음절을 버리지 않는다. 단발 녹음을 명시한 호출은 작은 첫소리를 100–800ms 범위에서 보완한다. 같은 파형의 짧은 배경 소리와 사람 목소리를 RMS만으로 완전히 구별하지는 못한다. 녹음 상한은 모두 12초다. STT가 만든 중간 문자열은 채점하지 않고 한 녹음의 최종 문장을 해석한다.

기존 발음 보완도 공유 판정에서 유지한다. “음 캐냐”·“정답은 캐냐예요”·“사우디 아라”처럼 알려진 말머리·말끝과 띄어쓰기를 정리한 이름 한 덩어리가 전체 목록에서 유일할 때만 인정한다. 질문·부정·여러 후보·일반 문장의 일부는 발음 보완으로 답을 만들지 않는다. 수도 이름·힌트 읽기 중 글 입력이나 마이크 멈춤을 선택하면 늦은 낭독 완료로 마이크를 다시 켜지 않으며, 완료 이벤트가 빠진 경우에는 7초 뒤 같은 문제의 듣기를 복구한다.

모든 질문형 놀이에서 정답이면 이름만 짧게 읽고, 오답·“몰라요”·건너뛰기는 정답과 설명을 끝까지 읽은 뒤 자동으로 다음 문제로 넘어간다. 설명 종료 뒤 900ms, 읽어주기를 끈 경우 1.8초 뒤 진행한다. 낭독 완료 이벤트가 누락되거나 재생에 실패한 경우에도 자동 다음 안전장치를 유지하며, 이름 안내는 최대 7초·전체 설명과 다시 듣기는 최대 21초의 완료 대기를 둔다. 마지막 문제는 결과 화면으로 간다. 선물은 현재의 작은 알림으로 보여 주고 확인 버튼이나 초점 이동으로 문제를 막지 않는다.

나라 이어 말하기는 인정한 나라 이름을 읽고 상대 차례의 녹음을 이어간다. 읽는 동안 마이크 입력을 음소거하고 시작 버튼을 잠그며, 읽기가 끝나면 고정 지연 없이 같은 마이크로 다음 차례를 준비한다. 실제 녹음 전에는 준비 비프가 끝나면 말하도록 안내한다. 소리 없는 연속 대기는 기기 안에서 녹음 구간만 교체하고 비프·유료 전사·듣기 상태 전환을 반복하지 않는다. 여러 나라·모르는 이름·망설임은 현재 차례와 지도·기록을 유지하며 자동으로 이어 듣는다. 이미 나온 유효한 나라의 중복은 기존처럼 같은 차례에서 다른 나라를 다시 선택하게 한다. 이 재시도는 퀴즈의 오답 자동 다음과 구별한다.

## 녹음 후 전사 경로의 서버 계약

```mermaid
flowchart LR
  A[현재 사람의 짧은 녹음] --> B[브라우저 메모리의 16kHz 단일 채널 WAV]
  B --> C[같은 origin의 NAS API]
  C --> D[세션·Origin·CSRF·중앙 권한·음성 길이·사용량 검사]
  D --> E[메모리의 PCM을 Soniox 실시간 STT에 전송]
  E --> F[공유 규칙으로 최종 답 선택]
  F --> G[원문·선택 결과·플레이어·차례 식별자]
  F -->|선택 설정과 엄격한 조건 충족| J[최신 권한 재확인과 최대 3초 Jev 최종 선택]
  J --> G
  G --> H[브라우저 재검증과 정식 이름 채점]
  H --> I[이름 또는 전체 설명 재생 뒤 다음 문제 · 미해석은 같은 문제 재답변]
```

- `js/cloud-speech.js`가 `getUserMedia`·`MediaRecorder`로 녹음하고 16kHz·16bit·단일 채널 PCM WAV로 변환한다. API 키와 원본 녹음을 브라우저 저장소에 보관하지 않는다.
- `js/speech.js`가 퀴즈의 시작·상태·결과·오류 콜백과 마이크 수명을 연결한다. TTS나 화면 이동 전에 `stopAnd`·`abort`는 녹음과 전사를 취소한다. 읽어주기 재생 때문에 새로운 유료 전사를 보내지 않는다.
- `js/spoken-answer.js`는 현재 문제 정답을 받지 않는 순수 규칙이다. 서버도 같은 브라우저 소스와 나라·수도 자료를 읽어 사용하며, 브라우저는 선택 결과를 다시 검사하고 정식 이름 하나만 기존 채점에 넣는다.
- `/api/speech`에는 세션 쿠키와 `X-CSRF-Token`, `X-Audio-Duration-Ms`, `X-Speech-Mode`, `X-Player-Id`, `X-Turn-Id`를 보낸다. 서버는 `voice`·`capitalVoice`·`country-chain`만 허용하고 실제 WAV 표본 수로 최대 12초·2MiB를 검사한다.
- 세션·같은 Origin·CSRF·최신 중앙 권한을 확인한 뒤 사용량을 영속 예약하고 Soniox `stt-rt-v5` WebSocket에 한국어 `ko` 전사를 요청한다. 세 모드는 사용자당 하루 120회·서비스 전체 월 3,000회의 기존 한도를 함께 사용한다. 날짜 경계는 UTC이며 최고 관리자도 같은 한도다.
- WAV의 PCM을 서버 메모리에서 100ms 단위로 읽어 송신 완료 callback을 확인하며 실제 오디오 속도로 전달한다. 녹음 종료 뒤 녹음 길이만큼의 전송 대기가 더해지는 대체 경로이며, 최대 12초 녹음·전사 시작부터 결과까지 전체 20초 제한을 둔다. 공급자 파일 업로드·비동기 전사 리소스는 생성하지 않는다.
- `context`·`prompt`와 현재 문제의 나라·수도 정답·선택지는 STT에 전달하지 않는다. 사용량 로그 식별자는 두 경로 모두 개인정보 없는 `flagquiz-rt:<UUID>`다. 플레이어·차례 식별자는 앱 응답의 연결 용도이며 인증이나 사용량의 주체는 서버 세션이다. 실패한 유료 연결은 자동 재시도하지 않는다.
- 성공 응답은 STT 원문 `text`와 최종 선택 `resolution`(`status`·`code`·정식 이름 `text`·`reason`·`source`)을 함께 보낸다. 브라우저는 플레이어·차례·화면 세대와 자체 규칙을 재검사한다. 새 문제·새 판·수동 입력·화면 숨김·이동 이후 도착한 이전 응답은 현재 놀이에 적용하지 않는다. 브라우저와 서버는 녹음을 메모리에서 처리하고 앱의 디스크나 학습 기록에 저장하지 않는다.

`server/answer-resolution.mjs`의 Jev 최종 선택은 선택 설정 `TYPESAFE_API_KEY`가 있을 때 활성화된다. 규칙이 명확히 찾은 답도 실제 후보 하나와 `unresolved`·`giveup` 선택지를 보내 `jev-1.13.0`의 선택을 확인한다. 미해석한 복잡한 문장은 실제 복수 후보와 명시적 최종 선택이 있는 경우에만 보완한다. 전사당 최대 한 번·3초이며, 유료 모델 호출 직전에 최신 중앙 권한을 다시 확인한다. 부정·인용·선택 질문·지시 조작과 단순 나열은 모델 선택으로 덮지 않고, 이미 명확하게 고른 답을 앞선 다른 후보로 바꾸지도 않는다. 현재 문제의 정답과 보기는 모델에 보내지 않는다.

후보 밖 결과·낮은 확신·미설정·장애·시간 초과는 순수 규칙의 답 또는 재답변으로 돌아간다. 명시적 포기는 순수 규칙이 확인한 경우에만 인정한다. 중앙 권한 회수는 모델 장애로 취급해 우회하지 않고 요청을 막는다. 앞선 실제 API 합성 비교 39건과 현재 선택 규칙의 세부 집계·한계는 [최종 답 규칙](spoken-answer-intent.md#확인-범위)에 기록한다. 아래 운영 검증은 과거 공급자 경로의 별도 증거이며 현재 Soniox 녹음 후 경로나 실제 어린이 발화 정확도를 증명하지 않는다. Soniox STT와 순수 규칙은 Jev 키 없이 사용할 수 있다.

요청·전사·취소의 서버 비용 한도와 보관 정책은 [서버 안내](../server/README.md#유료-말하기와-영속-저장)에 있다. 해당 문서의 2026-10-03 Groq 요금 계산은 과거 기록이며 현재 Soniox 비용 예측에 적용하지 않는다. 문맥 제거 후 실제 청구액과 어린이 인식 정확도는 별도 검증 대상이다.

## 연결과 기기 조건

운영 말하기에는 **인터넷·TechJuice ID 로그인·HTTPS·마이크 허용**이 필요하다. 브라우저의 `getUserMedia`·`MediaRecorder`·오디오 변환 지원 여부를 확인하고, 지원하지 않거나 거부되면 같은 문제에서 글자로 답한다. 받아쓰기 활성화 설정을 요구하지 않는다. localhost 정적 `?preview=1`은 인증과 STT를 연결하지 않고 수동 입력으로 놀이를 검토한다.

놀이 중 오프라인이 되면 기존 `continueWithTouch()`를 사용한다. 국기 말하기는 나라 이름과 국기 선택, 수도 말하기는 수도 듣기와 국기 선택으로 바꾸며 같은 문제·차례·점수·힌트·남은 시간을 유지한다. 온라인으로 돌아와도 현재 문제를 바꾸지 않고 다음 음성 문제부터 녹음을 다시 연다. 나라 이어 말하기는 같은 차례의 글자 입력을 제공한다.

보호된 NAS 앱은 로그인한 기기의 service worker에 앱 셸과 정적 음원을 저장할 수 있다. 서버에서 확인한 세션의 만료기한 안에서만 저장본을 열며 음성 인식 API·전사 응답은 저장하지 않는다. 저장·재실행 범위와 실제 기기 검증의 한계는 [오프라인 점검](offline-support-2026-10-09.md)에 기록한다. 오프라인에서는 Soniox 대신 로컬 STT를 실행하지 않고 같은 문제의 선택·글자 입력을 제공한다.

## 검증 범위

[최초 NAS 운영 기록](nas-deploy.md#최초-성공-운영-기록)에는 별도 최초 배포 SHA의 실제 로그인·외부 HTTPS·Groq 전사·운영 백업과 복원·재시작 후 상태 유지가 있다. 합성 대한민국 WAV의 운영 전사 성공은 서버 경로의 증거이며 실제 어린이 마이크 발화 정확도를 증명하지 않는다.

이번 모든 말하기 경로 통합은 별도의 변경이다. 자동 검사는 다음을 확인한다.

1. 세 말하기 모드의 요청·최종 결과 연결, 문맥·프롬프트·현재 정답 미전달과 개인정보 없는 사용량 식별자.
   최종 답 선택은 문장 반전·별칭·부분 겹침과 실제 후보를 검사하고, 규칙 밖 문장은 재답변으로 남긴다.
2. 권한·정리·전사 대기 중 제한시간 보존과 녹음 중 시간 측정.
3. 무음·오류·한도·인증 실패에서 같은 문제 유지와 수동 입력·마이크 재시도, 자동 유료 재시도 없음.
4. 수동 답변·홈 이동·숨김·새 문제 이후 늦은 응답 취소, TTS와 녹음 중복 방지.
5. 준비 비프 종료 전 녹음 차단·취소 뒤 늦은 비프 차단·효과음 OFF에서도 준비음 재생·비프 실패 시 녹음 차단. 비프 종료 직후 첫 PCM과 다음 차례 마이크 재사용 검증.
6. 정답 이름과 오답·포기 전체 설명 뒤 자동 다음·보상 비차단·마지막 결과 화면·오프라인 선택형 전환.

2026-10-04 NAS 배포 **run 585**, SHA `57810302aa60beb912500fe822e144f921676f9f`가 성공했다. 같은 배포에서 공개 합성 스웨덴·일본·스톡홀름 음성 3건이 실제 Groq STT와 Jev를 거쳐 모두 올바른 답·`source: jev`로 확인됐다. 이전 한국어 선택 안내가 단독 이름을 미확정으로 취급하던 결과를 대조한 뒤, 단독 이름과 같은 이름 반복도 하나의 완결된 답이라는 검증된 안내를 적용했다.

같은 3건의 NAS 요청 왕복은 1,167·943·1,241ms였다. `Server-Timing`의 최초 최신 권한 확인은 37·29·23ms, STT는 388·343·360ms, 최종 선택은 309·255·289ms였다. 최종 선택에는 호출 직전 권한 재확인 30·32·32ms가 포함되므로 별도로 더하지 않는다. 당시 200ms 종료 설정의 Chrome에서 측정한 말끝 감지·녹음 정리 약 234ms를 합산하면 **말끝부터 답까지 약 1.18~1.48초로 추정되어 0.5~1초 목표에 미달한다.** NAS 수치는 실제 합성 요청의 측정이고, 합산값은 실제 어린이 발화의 종단 측정이 아니다. 이 측정은 800ms 종료 보완 전의 기록이며 현재 녹음 대기 시간을 나타내지 않는다. 다음 단계의 제공자 비교와 지연 기준은 [스트리밍 STT 설계](streaming-speech-design.md)에 정리한다.

iPhone/iPad에서 실제 어린이 목소리, 권한 허용·거부·재시도, 나라·수도 인식 정확도와 지연, 두 사람의 연속 차례는 실제 기기 검사로 확인해야 한다. 이 문서 작성 시점에 해당 기기 검사를 완료로 표시하지 않는다.

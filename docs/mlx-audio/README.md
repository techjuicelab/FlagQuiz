# FlagQuiz: MLX Core 음악 제작 팩

2026-09-11 · MLX Core 26.8.11의 실제 화면과 설치 모델을 확인해 작성했다.

**16종 모두 MLX Core 로컬 API로 생성하고, 짧게 편집해 앱에 연결했다. 생성 설정과 원본 WAV는 `docs/artifacts/mlx-music/raw/`, 앱용 MP3는 `audio/music/`에 있다.**

## 먼저 들어 볼 세 가지

1. **01 작은 나무상자**: 앱의 대표 상자 소리. 나무 오르골·칼림바·작은 벨.

기본 탐험 모드는 정오답에 같은 발견음을 쓴다. 정답 전용 2종은 홈의 정답 음악을 켰을 때 사용하며, 기본 탐험 모드에서는 생략한다.

[설치 모델 공식 카드](https://huggingface.co/ddalcu/ACE-Step-1.5-XL-Turbo-MLX-Serve-8bit/blob/3fec8ac6882464d21c96434744ec184c236a5d06/README.md)

프롬프트의 “처음 3초 안에 끝내기”는 작곡 방향이다. 실제 악구 위치·무음·음량·악기·종료 시간을 보장하지 않는다. 이 모델은 음악 생성 모델이므로 특히 1초 미만 효과음은 **좋은 한두 음을 골라 잘라 쓰는 방식**으로 접근한다.

## 생성하고 보관하는 순서

1. 해당 Style prompt를 붙여 넣고 표의 숫자와 조성을 맞춘다.
2. Instrumental이 켜져 있는지 확인하고 Generate를 누른다.
3. History의 재생 버튼으로 듣고, 폴더 버튼으로 원본을 확인한다.
4. 원본 WAV와 함께 만들어지는 설정 기록 TXT를 함께 보관한다. 현재 앱이 보여 준 출력 폴더는 `/Users/techjuice/.mlx-serve/generations/music`이다.
5. 원본을 유지하고 사본에 `fq-chest-01-musicbox-seed41101.wav`처럼 곡 ID와 실제 Seed를 붙인다.
6. 소리가 완결되는 부분을 골라 편집한다. 세부 범위는 실제로 듣고 결정한다.
7. 앱용은 `fq-chest-01-musicbox.mp3`처럼 내보낸다. WAV 원본을 MP3로 덮어쓰지 않는다.

설정 TXT 저장 동작은 [공식 생성 서비스 소스](https://github.com/ddalcu/mlx-serve/blob/main/app/Sources/MLXServe/Services/MusicGenService.swift), Examples의 저장 동작과 UI는 [공식 화면 소스](https://github.com/ddalcu/mlx-serve/blob/main/app/Sources/MLXServe/Views/MusicGenView.swift)에서 확인했다.

## 짧은 음원으로 편집하기

- **발견 0.4~0.9초**, 정답 0.7~1.3초, 상자 2.5~3.5초, 완료 3~4초를 시작점으로 잡는다.
- 앞의 긴 무음은 잘라낸다. 첫 음이 잘리지 않도록 약 10~30ms 여유를 두고 듣는다.
- 시작 10~25ms, 끝 100~250ms 정도의 짧은 페이드를 출발점으로 쓰되 실제 잔향에 맞춘다. 짧은 발견음은 더 짧은 페이드가 필요할 수 있다.
- 멜로디 중간을 기계적으로 3초에서 끊지 않는다. 짧고 자연스럽게 닫히는 테이크를 선택한다.
- 음원끼리 체감 음량을 맞추고 Sua보다 작게 시작한다. 피크는 우선 -6dBFS 정도 이하로 두고 실제 기기의 작은 스피커에서 조정한다. 이 수치만으로 체감 음량이나 편안함이 정해지지는 않는다.
- 추천 앱 배포 사본은 MP3, stereo, 48kHz, 128kbps다. 긴 BGM은 루프 경계를 따로 들어 본다.
- 말소리·노랫소리·갑자기 큰 타격음·찢어짐·날카로운 고음이 섞인 테이크는 선택하지 않는다.

너무 긴 전주가 생기면 Style prompt 끝에 아래 문장을 붙여 다시 비교한다.

> A single isolated musical gesture begins immediately; no introduction and no continuing accompaniment.

멜로디가 여러 번 반복되면 첫 번째로 자연스럽게 끝나는 악구만 고른다. 그래도 효과음으로 쓰기 어렵다면 발견음은 기존 Web Audio의 짧은 둥근 음을 유지하고 MLX 음악을 상자·완료 장면에 집중한다.

## 앱에 적용한 발견 반응

**오답을 위로하는 장면보다, 국기의 특징을 같이 발견하는 장면을 제안한다.** 아래 문구는 정답·다른 답·모르겠어요 모두의 학습 카드에서 쓸 수 있다. 화면에만 표시하며 Sua 앞뒤에 응원 대사를 추가하지 않는다.

| 화면 문구 | 작은 화면 반응 | 연결할 소리 |
|---|---|---|
| 국기를 펼쳐요 | 카드가 조용히 펼쳐짐 | 여행책 한 장 |
| 색을 따라가요 | 국기의 색을 한 번 가볍게 강조 | 깃발이 살랑 |
| 지도에 톡 | 지도 점이 살짝 커졌다 돌아옴 | 지도에 톡 |
| 깃발이 살랑 | 국기 모서리가 한 번 움직임 | 깃발이 살랑 |
| 여행책에 한 장 | 카드가 여행책에 들어감 | 여행책 한 장 |
| 하나 더 만났어요 | 카드 둘레에 작은 빛 점 | 지도에 톡 |

말로는 기존 요청 그대로 **나라 이름 한 번 + 쉬운 특징 한 문장**만 읽는다. 예: “일본. 하얀 바탕에 빨간 동그라미가 있어요.” 수도 문제는 수도 이름 한 번 뒤에 어느 나라의 수도인지 한 문장만 이어진다. “괜찮아”, “다음엔 잘할 거야”, “다시 생각해 봐”처럼 실패를 재차 떠올리는 말은 붙이지 않는다. 다시 듣기는 아이가 눌렀을 때만 반복한다.

오답에만 발견음을 붙이면 그 소리도 오답 신호가 될 수 있다. 같은 카드 공개 과정에 정오답 공통으로 연결하고, 짧은 화면 반응 하나만 사용한다. 모든 반응을 한꺼번에 겹치지 않는다.

## 누적 여행 카드 보상

이전 버전은 5연속 정답에 상자를 지급하고, 다른 답이면 streak가 0이 됐다. 이번에는 전체 누적 학습 카드 수를 상자 진행에 사용하고, 힌트 감점도 제거했다. 정확도와 기존 점수 기록은 사실대로 보존한다.

적용한 기본 흐름은 **학습 카드 다섯 장을 만나면 상자 열기**다. 정답·다른 답·모르겠어요 모두 한 문제당 한 장을 쌓고, 이미 쌓인 진도는 줄지 않는다. 다시 듣기·버튼 중복·다시 렌더링은 추가 적립하지 않는다. 정확도 기록은 사실대로 따로 남긴다. 화면에는 “여행책에 다섯 장이 모였어요”라고 보여 준다.

상자 6종은 같은 가치로 순환하고 직전 음악은 연속으로 고르지 않는다. 희귀 등급·당첨 실패·소리 크기 경쟁을 만들지 않는다. 힌트에는 “같이 보기”, 복습 버튼에는 “한 번 더 만나기”처럼 행동을 표현한다. 결과는 “오늘 만난 나라”를 중심으로 보여 주는 안이다. 점수·정답률·실제 학습 기록의 삭제나 거짓 성공 처리는 제안하지 않는다.

이것은 부담을 줄이기 위한 설계안이다. 실제로 아이가 어떻게 느끼는지는 사용 반응으로 확인해야 한다.

## 앱에 붙일 때의 순서와 연결표

이전 950ms 상자 타이머를 제거했다. 이제 Sua 설명의 실제 종료 뒤 상자와 해당 음악이 나오며, 홈·도감 BGM도 마이크 종료가 완료된 뒤 시작한다.

| 이벤트 | 후보 ID | 적용 규칙 |
|---|---|---|
| 학습 카드 공개 | discover-01~03 | 정오답 공통. 쓸 경우 짧게 재생한 뒤 Sua 시작 |
| 정답 확인 (선택 옵션) | correct-01~02 | 기본 탐험 모드에서는 생략. 켠 경우 발견음과 겹치지 않고 연속 횟수에 따라 커지지 않음 |
| 여행 상자 | chest-01~06 | Sua 설명 완료 후 상자와 함께 1곡. 다른 축하 효과음 생략 |
| 새 스티커 | sticker-01 | 상자와 동시에 얻으면 소리는 상자 하나만 |
| 새 탐험 단계 | level-01 | 상자와 겹치면 생략 |
| 한 판 완료 | finish-01 | 점수와 관계없이 같은 음악. Sua와 순서대로 |
| 시작 버튼 | start-01 | 사용자 클릭 후 한 번 |
| 홈·도감 | home-01 | 선택 옵션, 기본 꺼짐. 퀴즈·마이크·Sua 시작 전 정지 |

이벤트가 겹치면 **상자 > 탐험 단계 > 스티커 > 정답/발견** 중 하나만 고른다. 학습 설명을 우선하며, 음성 재생이 실패해도 화면·다음 버튼을 막지 않는다. 음성을 꺼둔 경우에는 설명 대기 없이 효과음 설정에 따라 음악을 재생한다.

닫기·다음·그만하기·탭 숨김·마이크 시작 시 재생과 예약을 취소한다. 음악 길이만큼 버튼을 잠그거나 다음 문제를 자동으로 넘기지 않는다. 움직임 줄이기 설정에는 정적인 카드를 쓴다.

앱 음원은 `audio/music/`와 `js/music-manifest.js`에 연결했다. 배포 빌드는 16곡의 이벤트 분포·파일 경로·길이·SHA-256 일치를 확인해 복사한다. 제작 계획 `presets.json`과 실행용 manifest는 별도로 보존한다.

## 실제 생성 및 검증 기록

- `node scripts/generate-music.mjs`: 설치 모델 사용, 완료 원본 해시를 확인해 재사용한다. 기본 주소는 로컬 `127.0.0.1:11234`다.
- `node scripts/prepare-music.mjs --ffmpeg <ffmpeg 실행 파일>`: 원본 보존, 에너지 기반 시작·끝 선정, 짧은 페이드, 음량 조정 후 앱용 MP3를 만든다.
- 생성 WAV 16개, 앱 MP3 16개(총 978,752바이트). 상자 약 2.9~3.4초, 발견음 약 0.6~0.7초, 배경음 28초다.
- 16개 MP3를 모두 디코딩해 길이·파형·피크·클리핑을 검사했다. 자세한 수치는 `docs/artifacts/mlx-music/edit-report.json`에 있다.
- 로컬 Gemma 보조 청취 검수는 제어 음성도 인식하지 못해 유효 결과 0개였다. 이를 청취 통과나 음원 결함의 근거로 사용하지 않았다. 청감과 아이의 반응은 실제 재생에서 확인해야 한다.

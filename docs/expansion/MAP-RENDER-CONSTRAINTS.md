# 지도 렌더링 제약

지도 자산을 사용하는 후속 화면 구현의 필수 계약이다. 지도 채점 단위는 아직 결정되지 않았고, 아래 규칙은 나라·대륙 어느 쪽에도 적용한다.

## 1. 핀은 SVG 위의 HTML 버튼

- 규칙: 육지는 `viewBox="0 0 2000 1000"`인 SVG의 단색 `<path>` 한 개로 그리고, 핀은 같은 컨테이너 위의 `position:absolute` HTML `<button type="button">`으로 반드시 겹친다. 위치는 `[lng, lat]`로부터 `left=(lng+180)/360*100%`, `top=(90-lat)/180*100%`, 중앙 정렬은 `translate(-50%,-50%)`로 계산한다. 사전 계산 x/y를 저장하지 마라.
- 근거: `docs/expansion/DECISIONS.md:60` 좌표 계약, `:67` 고정 크기 핀, `:75` 좌표 공식.
- 위반 증상: SVG 내부 핀은 화면 폭에 따라 작아져 터치 타깃이 달라지고, 저장한 화면 좌표는 지도 변경 시 어긋난다.

## 2. 터치 영역은 최소 44px

- 규칙: 버튼에 `min-width:44px; min-height:44px`를 주고 투명한 탭 영역 안에 보이는 점 16~20px을 따로 둔다. 국가 도형을 탭 대상으로 삼지 마라.
- 근거: `design/SPEC.md:37`, `docs/expansion/DECISIONS.md:67`.
- 위반 증상: 작은 나라나 좁은 화면에서 아이가 정답을 알아도 누를 수 없다.

## 3. 동시에 최대 5개 핀

- 규칙: 한 문제에 필요한 핀만 최대 5개 표시한다. 화면 좌표 간 거리가 44px 미만인 후보 조합은 버리고 다시 고른다.
- 근거: `design/SPEC.md:37`, `docs/expansion/HANDOFF.md:966`.
- 위반 증상: 유럽 등에서 버튼이 겹쳐 엉뚱한 나라가 눌린다.

## 4. 핀은 반드시 #main 안에 둔다

- 규칙: 핀 요소는 `#main`의 자손으로 둔다. `document.body`에 붙이지 마라.
- 근거: `js/ui.js:17`의 `setMain`, `js/effects.js:88`·`:89`의 body 부착 후 자체 제거 예외.
- 위반 증상: 홈으로 나간 뒤에도 핀이 남거나 중복된다. `#main` 안이면 화면 교체가 함께 치운다.

## 5. 반복 실행 루프 금지

- 규칙: `requestAnimationFrame`·`setInterval`을 사용하지 마라. `setTimeout`은 자기 자신을 끝내는 1회성 작업에만 허용하고 대상 노드가 사라졌는지 방어한다.
- 근거: `docs/expansion/DECISIONS.md:78`, `js/app.js:62`의 화면 자원 정리.
- 위반 증상: 화면을 떠난 뒤에도 계산이 돌아 재진입할수록 느려진다.

## 6. 움직임은 CSS transition으로만

- 규칙: `@keyframes`를 사용하지 마라. 표시 상태 간 변화는 CSS `transition`으로만 정의한다.
- 근거: `css/style.css:531`의 움직임 줄이기 규칙은 animation과 transition을 모두 끈다.
- 위반 증상: 애니메이션의 완료에 정답 표시를 맡기면 움직임 줄이기에서 정답이 나타나지 않는다.

## 7. 기본 CSS는 항상 정답 상태

- 규칙: `.map-pin` 기본값은 제자리·`opacity:1`이다. `.is-entering` 일시 클래스만 출발 상태를 나타내며 다음 표시 시점에 제거한다. 상태 제거를 애니메이션 완료 이벤트에 의존시키지 마라.
- 근거: `docs/expansion/DECISIONS.md:81`, `css/style.css:531`.
- 위반 증상: 기본 상태를 숨김으로 두고 애니메이션이 보여주게 하면 움직임 줄이기에서 영원히 투명할 수 있다.

## 8. 움직임 줄이기 분기는 CSS 한 곳

- 규칙: 핀에 대한 JavaScript 움직임 줄이기 감지 분기를 추가하지 마라. 움직임이 없어도 기본 정답 상태가 그대로 보여야 한다.
- 근거: `js/effects.js:7`의 감지는 생략 가능한 색종이용이며, 정답 핀은 `docs/expansion/DECISIONS.md:81`에서 반드시 보여야 하는 결과다.
- 위반 증상: 색종이처럼 핀 생성을 건너뛰면 채점 결과까지 사라진다.

## 9. 기존 색 토큰 사용

- 규칙: 핀·육지·바다는 `--primary`·`--success`·`--danger`·`--accent`·`--card`·`--line` 등 기존 토큰으로 정한다. 밝은 화면과 다크 화면 양쪽에서 육지와 바다를 구분한다.
- 근거: `css/style.css:6`의 기본 토큰과 `:27`의 다크 토큰.
- 위반 증상: 고정 색을 새로 넣으면 다크 화면에서 육지나 핀이 배경에 묻힌다.

## 10. 나라 이름과 정답을 텍스트로 알린다

- 규칙: 모든 핀 버튼에 한글 나라 이름 `aria-label`을 두고 정답은 `#main` 안에 글자로 함께 표시한다. 색만으로 정답을 알리지 마라.
- 근거: `index.html:32`의 `aria-live="polite"`.
- 위반 증상: 화면 읽기 도구나 색 구별이 어려운 사용자가 선택과 결과를 알 수 없다.

## 11. 채점 기준은 렌더링과 분리

- 규칙: 핀 좌표는 나라 단위로 보유하되, 채점 해상도와 허용 반경은 별도 채점 코드의 상수로 둔다. 나라·대륙 중 무엇을 채점할지는 사용자 결정 전까지 고정하지 마라.
- 근거: `docs/expansion/DECISIONS.md:87`의 현실적 목표와 `docs/expansion/HANDOFF.md:1286`의 미정 사항.
- 위반 증상: 화면 크기나 핀 크기를 바꾸는 일이 정답 기준까지 바꾸게 된다.

## 실기기 확인표

- [ ] 아이패드 접근성의 동작 줄이기를 켜도 정답 핀이 즉시 보인다.
- [ ] 바티칸·모나코를 한 번에 누를 수 있다.
- [ ] 홈으로 나갔다 들어오기를 10번 반복해도 느려지지 않는다.
- [ ] 다크 모드에서 육지·바다·핀이 구분된다.

가짜 DOM 테스트는 이 확인을 대신하지 않는다. 지도 화면을 실제로 구현한 뒤 실기기 결과를 기록한다.

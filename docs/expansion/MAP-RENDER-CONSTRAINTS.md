# 지도 렌더링 제약

지도 자산을 사용하는 화면의 필수 계약이다. 현재 채점 방식은 **나라 위치 번호 네 개 중 하나를 고르는 퀴즈**이며, 지도 공부는 채점 없이 별도로 이용한다. 나라 이어 말하기는 이미 말한 나라를 누적하는 기록 지도이며, 퀴즈 보기 수 제한을 적용하지 않는다.

2026-09-26 개편에서는 사용자의 지도 공부·퀴즈 분리, 더 큰 지도, 대륙과 정확한 위치 안내 요청을 반영했다. 초기 설계의 좌표·터치·화면 수명 원칙은 유지한다. 아래에서 현재 구현으로 달라진 사항과 이유를 명시하며, `DECISIONS.md`와 `HANDOFF.md`의 당시 미정 사항은 설계 이력으로 남긴다.

## 1. 핀은 SVG 위의 HTML 버튼

- 규칙: 퀴즈 육지는 `viewBox="0 0 2000 1000"`인 SVG의 단색 `<path>`로 그리고, 핀은 같은 컨테이너 위의 `position:absolute` HTML `<button type="button">`으로 겹친다. 위치는 `[lng, lat]`에서 `left=(lng+180)/360*100%`, `top=(90-lat)/180*100%`, 중앙 정렬은 `translate(-50%,-50%)`로 계산한다. 사전 계산 x/y를 저장하지 마라. 세계는 2:1, 지역 확대는 같은 투영을 잘라 낸 4:3 영역이며 지형을 늘리지 않는다. 날짜변경선을 넘는 확대 지도만 같은 육지 경로를 옆에 복사해 이어 붙인다.
- 근거: `docs/expansion/DECISIONS.md:60-72`의 원좌표·투영 계약, `js/map.js:236-251`의 확대 지도와 날짜변경선 처리, `js/map.js:267-282`의 퀴즈 렌더링.
- 위반 증상: SVG 내부 핀은 화면 폭에 따라 작아져 터치 타깃이 달라지고, 저장한 화면 좌표나 비율을 늘린 지형은 실제 위치를 오해하게 한다.

## 2. 터치 영역은 최소 44px

- 규칙: 버튼의 너비·높이는 44px로 유지하고, 그 중심에 작은 위치 점을 따로 둔다. 번호 표시는 점 위에 놓는다. 국가 도형을 탭 대상으로 삼지 마라. 초기의 보이는 점 16~20px 지침은 2026-09-26에 위치 점 9px와 번호 표시 25~28px로 분리했다. 큰 번호가 주변 지형을 가리지 않으면서 실제 좌표를 알리기 위한 변경이며, 터치 영역은 줄이지 않았다.
- 근거: `design/SPEC.md:37`의 최소 44px, `css/map.css:46-78`의 고정 터치 영역·좌표 점·번호 표시.
- 위반 증상: 작은 나라나 좁은 화면에서 아이가 정답을 알아도 누를 수 없거나, 큰 번호의 어느 부분이 실제 위치인지 알 수 없다.

## 3. 퀴즈는 동시에 최대 5개 핀

- 규칙: 초기 상한인 최대 5개를 유지하되, 현재 퀴즈는 정확히 4개를 표시한다. 44px 사각형 터치 영역이 겹치는 후보 조합은 제외한다. 최소 판 너비 280px·양쪽 여백 22px를 기준으로도 검사하여 화면 회전 후 보기를 다시 고르지 않는다. 중심 사이 직선 거리만 검사해서는 안 된다. 나라 이어 말하기에서는 정답 보기가 아닌 기록을 모두 표시하므로 최대 194개를 누적한다. 실제 좌표를 옮기지 않고 넓은 지도를 좌우로 볼 수 있게 하며, 선택한 나라가 보이도록 가운데로 이동한다. 가까운 위치의 기록은 아래 나라 목록에서 각각 선택할 수 있다.
- 근거: `design/SPEC.md:37`, `js/map.js:27-80`의 최소 크기와 사각형 분리 검사.
- 위반 증상: 유럽 등에서 버튼이 겹쳐 엉뚱한 나라가 눌리거나, 화면을 회전한 뒤 정답 번호가 바뀐다.

## 4. 핀은 반드시 #main 안에 둔다

- 규칙: 퀴즈 핀과 공부용 위치 표시는 `#main`의 자손으로 둔다. `document.body`에 붙이지 마라. 공부용 표시는 버튼이 아닌 설명용 요소이며 화면 읽기 도구에는 나라와 좌표 설명을 제공한다.
- 근거: `js/ui.js:82-93`의 `setMain`, `js/map.js:254-264`의 공부용 표기, `js/effects.js:88-89`의 body 부착 후 자체 제거 예외.
- 위반 증상: 홈으로 나간 뒤에도 핀이 남거나 중복된다. `#main` 안이면 화면 교체가 함께 치운다.

## 5. 반복 실행 루프 금지

- 규칙: 지도 렌더링에 `requestAnimationFrame`·`setInterval`을 사용하지 마라. `setTimeout`은 자기 자신을 끝내는 1회성 작업에만 허용하고 대상 노드가 사라졌는지 방어한다. 현재 지도 렌더러는 정적 마크업만 생성한다.
- 근거: `docs/expansion/DECISIONS.md:74-76`, `js/app.js:656-665`의 화면 자원 정리.
- 위반 증상: 화면을 떠난 뒤에도 계산이 돌아 재진입할수록 느려진다.

## 6. 움직임은 CSS transition으로만

- 규칙: 지도 표시에는 `@keyframes` 사용을 금지한다. 움직임을 추가한다면 표시 상태 간 CSS `transition`으로만 정의한다. 현재 핀과 위치 표시는 움직임 없이 즉시 나타난다.
- 근거: `css/style.css:671-673`의 움직임 줄이기 규칙은 animation과 transition을 모두 끈다.
- 위반 증상: 애니메이션의 완료에 정답 표시를 맡기면 움직임 줄이기에서 정답이 나타나지 않는다.

## 7. 기본 CSS는 항상 정답 상태

- 규칙: `.map-pin` 기본값은 제자리·`opacity:1`이다. 향후 움직임을 추가해도 `.is-entering` 같은 일시 클래스만 출발 상태를 나타내고 다음 표시 시점에 제거해야 한다. 상태 제거를 애니메이션 완료 이벤트에 의존시키지 마라. 여기서 기본 정답 상태는 위치가 즉시 보인다는 뜻이며, 답하기 전에 정답 나라를 공개한다는 뜻이 아니다.
- 근거: `docs/expansion/DECISIONS.md:77-79`, `css/map.css:47-67`, `css/style.css:671-673`.
- 위반 증상: 기본 상태를 숨김으로 두고 애니메이션이 보여주게 하면 움직임 줄이기에서 영원히 투명할 수 있다.

## 8. 움직임 줄이기 분기는 CSS 한 곳

- 규칙: 핀에 대한 JavaScript 움직임 줄이기 감지 분기를 추가하지 마라. 움직임이 없어도 기본 정답 상태가 그대로 보여야 한다.
- 근거: `js/effects.js:8-10`의 `reducedMotion` 감지는 생략 가능한 색종이용이며, 정답 핀은 `docs/expansion/DECISIONS.md:77-79`에서 반드시 보여야 하는 결과다.
- 위반 증상: 색종이처럼 핀 생성을 건너뛰면 채점 결과까지 사라진다.

## 9. 의미별 색 토큰과 밝은·어두운 화면 대응

- 규칙: 카드·테두리·본문은 기존 `--card`·`--line`·`--text` 등을 사용한다. 지도에는 육지·바다·대륙 이름·위치 점의 역할을 구분하는 `--map-land`·`--map-water`·`--map-label`·`--map-point`·`--map-halo` 토큰을 추가했고, 반드시 밝은 화면과 다크 화면 값을 함께 정의한다. 이는 기존 토큰만 사용하던 지침을 2026-09-26에 확장한 것으로, 넓어진 지도에서 육지와 라벨 대비를 따로 조정하기 위한 변경이다.
- 근거: `css/style.css:3-44`의 기본·다크 토큰, `css/map.css:10-16`의 지도 토큰, `css/map.css:197-204`의 지도 다크 토큰.
- 위반 증상: 한 테마에만 맞춘 고정 색을 사용하면 다른 테마에서 육지·글자·위치 점이 배경에 묻힌다.

## 10. 나라 이름과 정답을 텍스트로 알린다

- 규칙: 퀴즈 핀 버튼의 `aria-label`은 **위치 1~4**로 보이는 번호와 일치시킨다. 초기의 모든 핀에 나라 이름을 읽어 주라는 지침은 답을 고르기 전에 정답을 노출하므로 2026-09-26에 바꿨다. 문제의 나라 이름은 질문에, 정답 나라·대륙·확대 지도 설명은 `#main` 안의 정답 카드에 글자로 표시한다. 색만으로 정답을 알리지 마라.
- 근거: `js/map.js:273-280`의 선택 번호, `js/app.js:1181`의 `#feedback-area`는 `role="status" aria-live="polite"`로 정답 설명을 알린다. 전체 `#main`을 중복해서 읽지 않는다.
- 위반 증상: 나라 이름을 보기에서 먼저 읽어 주면 위치를 찾을 필요가 없어지고, 반대로 결과를 색으로만 알리면 화면 읽기 도구나 색 구별이 어려운 사용자가 답을 알 수 없다.

## 11. 채점 기준은 렌더링과 분리

- 규칙: 현재는 선택한 나라 코드와 문제 나라 코드가 같은지 채점한다. 지도 공부는 채점 함수와 기록 갱신을 호출하지 않는다. 나라·대륙 중 채점 단위가 미정이라는 초기 문구는 설계 이력이며, 현재 구현의 나라 사지선다를 미정 상태로 되돌리지 않는다. 터치 위치 반경으로 채점하지 않으므로 핀 크기나 확대 배율이 정답 기준을 바꾸어서는 안 된다.
- 근거: `docs/expansion/DECISIONS.md:83-84`의 초기 대륙 인식 목표, `js/quiz.js:632-643`의 실제 나라 코드 채점, `js/app.js:958-1000`의 별도 공부 흐름.
- 위반 증상: 화면 크기나 핀 크기를 바꾸는 일이 정답 기준까지 바꾸거나, 공부만 했는데 점수와 오답 기록이 생긴다.

## 실기기 확인표

- [ ] 아이패드 접근성의 동작 줄이기를 켜도 정답 위치가 즉시 보인다.
- [ ] 바티칸·모나코가 출제될 때 각 44px 버튼을 한 번에 누를 수 있다.
- [ ] 홈으로 나갔다 들어오기를 10번 반복해도 느려지지 않는다.
- [ ] 다크 모드에서 육지·바다·대륙 이름·위치 점이 구분된다.
- [ ] 아이폰과 아이패드에서 지도 공부의 세계 위치·주변 확대 지도·나라 이름을 읽을 수 있다.
- [ ] 비행기 모드에서 저장한 앱을 다시 열어 지도 공부·퀴즈·정답 지도를 볼 수 있다.

가짜 DOM 테스트나 데스크톱 브라우저의 화면 크기 에뮬레이션은 실기기 확인을 대신하지 않는다. 실제 기기에서 확인한 항목만 결과와 함께 체크한다.
